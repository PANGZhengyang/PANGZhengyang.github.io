# RAG

RAG是检索增强生成（Retrieval-Augmented Generation）：先从资料库里**检索**相关内容，再从这些内容来**生成**答案。

使用场景：智能客服、知识库搭建。

# 基本流程

准备（提问前）：分片、索引

回答（提问后）：召回、重排、生成

## 分片

把文档切分成多个片段，方式有很多种：

- 字数
- 片段
- 页码
- 章节
- 语义集合

## 索引

通过**Embedding**将片段文本转换为**向量**，将片段文本与片段向量存入**向量数据库中**

Embedding：将文本转换为向量的过程。语义相似的文本向量也越接近。文本与提问的问题都要使用相同的embedding，同样编码的相关信息在同一个坐标系下进行比较。

## 召回

搜索与用户问题相关的片段：

1、用户发送问题

2、embedding模型进行embedding，然后发送给向量数据库

3、返回最相似的结果（计算向量相似度：余弦相似度、欧式距离、点积）

## 重排

从召回里面再挑选与用户结果最相似的内容

```
为什么不在召回环节直接选取？
召回与重排两个阶段使用的文本相似度的逻辑不同,拆分成两个步骤效果更好。
召回使用的是向量相似度，特点是：成本低、耗时短、准确率低；适合初步筛选；（简历筛选）
重排使用的是cross-encoder，特点：成本高、耗时长、准确率高；适合精挑细选；（面试筛选）
```

## 生成

根据筛选出来的文本生成答案
