# 什么是MCP

MCP（Model Context Protocol，模型上下文协议），统一大模型与外部数据源和工具之间的通信协议。

MCP使得AI应用能够安全地访问和操作本地及远程数据，为AI应用提供链接万物的**接口**。

MCP规定了Tools的注册和使用，没有规定与模型的交互形式。

# MCP的价值

在过去，为了让大模型等 AI 应用使用数据，要么复制粘贴，要么上传知识库，非常局限。

即使是最强大模型也会受到数据隔离的限制，形成信息孤岛，要做出更强的大模型，每个新数据源都需要自己重新定制实现，使真正互联的系统难以扩展，存在很多的局限性。

现在，MCP 可以直接在 AI 与数据（包括本地数据和互联网数据）之间架起一座桥梁，通过 MCP 服务器和 MCP 客户端，大家只要都遵循这套协议，就能实现“万物互联”。

有了MCP，可以和数据和文件系统、开发工具、Web 和浏览器自动化、生产力和通信、各种社区生态能力全部集成，实现强大的协作工作能力，它的价值远不可估量。

# MCP协议架构

MCP的核心思想是将模型与外部世界之间的接口抽象为标准化协议，使LLM通过一致的方式访问各种资源和工具。MCP架构角色分工和连接关系：

![MCP-framework](/assets\machine learning\ML-ai-mcp\1.png)

## MCP架构的核心角色

| 角色          | 职责                                                         | 示例                        |
| ------------- | ------------------------------------------------------------ | --------------------------- |
| Host 主机     | 运行模型与用户界面，协调上下文与访问工具，Host内含有多个Client | Claude Desktop、Cursor      |
| Client 客户端 | 实现协议通信与消息翻译，将模型指令转为 Json-RPC 请求         | 内置连接器或插件            |
| Server 服务器 | 提供可调用工具（Tools）、资源（Resources）和提示词模版（Prompts)，每个Server只能看到自己的Client | Git、Filesystem、Playwright |

Host可同时连多个 Server（对应多个Client），是模型能够在同一上下文中调用不同系统资源。

Server 提供Tools、Resources、Prompts：

| 元素      | 功能                         | 示例                           |
| --------- | ---------------------------- | ------------------------------ |
| Tools     | （函数）主动调用的可执行操作 | 搜索文件、发起支付、查询sql    |
| Resources | 只读数据或订阅源             | 文件内容、数据库查询、文档索引 |
| Prompts   | 可复用提示模版或生成脚本     | 编码规范、工作流模版           |



## 交互流程

在安装MCP的时候， Host 会和 Server 进行交互，Server会告诉 Host 安装哪个 MCP，具体的Tools有哪些，每一个Tools 的描述（description），入参（InputSchema）有哪些；还会Host 也会问 Server 是否有Resources、Pormpts可用。

![MCP-installment](/assets\machine learning\ML-ai-mcp\2.png)

当用户开始在Host沟通，就进行下列的交互流程：

![MCP-Interaction Flow](/assets\machine learning\ML-ai-mcp\3.png)

Client 以JSON-RPC 向服务器发送调用请求，传输层设计两种传输类型（Transport type）：

| 传输类型 | 说明                                                         | 适用场景                  |
| -------- | ------------------------------------------------------------ | ------------------------- |
| STDIO    | 通过 Host 启动子进程，使用标准的**输入输出**传递 JSON-RPC 消息 | 本地插件、离线环境        |
| HTTP+SSE | Client 以 HTTP POST 发送请求， Server通过 SSE（Server-Sent Events） 流式响应 | 远程Server、云端 Saas服务 |

**MCP规定了Tools的注册和使用（Host 与 MCP Server之间的交互）**，没有规定Host与模型的交互形式（Host 与 LLM）。

例如：Cline与模型是通过XML方式交互的。



# MCP与Function Calling

MCP是Host与MCP Server之间的交互，是调用外部工具真正的执行；

Function Calling 是 Host 与 模型之间的交互，模型使用工具的能力，是一种思考决策的能力；

![MCP-Function Calling](/assets\machine learning\ML-ai-mcp\4.png)



# MCP和CLI

MCP是能够让大模型连接外部系统，是一套工具协议。

CLI（Command-Line Interface）是命令行程序，将API封装成命令供AI调用。

1. 调用效率：CLI一般与Skill配合，直接执行脚本，减少与大模型交互，节省Token；而MCP每次调用返回给大模型思考，效率低；

2. 上下文压力：CLI上下文占用小，但是MCP需加载全部目录信息，消耗token多。

## 流程

以高德CLI为例，流程如下：

1. 用户输入自然语言：如“查询周边 1km 咖啡店” 
2. SKILL发现：Agent识别用户意图匹配到对应的SKILL （也不一定需要skill，因为cli语句很成熟了，所以已经提前训练好了，大模型能够生成）
3. CLI命令构造：LLM 参考SKILL中的流程，将自然语言参数转换为完整的CLI命令，如下 amap-gui searchPOI --keyword 星巴克 --city 北京 --pageSize 1 
4.  执行CLI命令：Agent 直接在终端执行构造好的命令 
5. 请求后端接口：CLI 工具解析命令参数，构造并发起 HTTP 请求调用高德API 
6. 结果反馈：搜到的 POI 列表返回给 Agent，供其进一步处理 

对比高德MCP(StreamableHTTP)流程： 

1. 用户输入自然语言：如 “查询周边 1km 咖啡店” 
2. 工具发现：Agent识别用户意图匹配 MCP Server暴露的工具描述 
3. MCP 请求构造：LLM 参考 工具的input_schema，将自然语言参数转换为标准JSON-RPC消息 
4. 工具调用请求：MCP Client 通过 HTTP 向远程 MCP Server发tools/callRPC消息，包含请求参数 
5. 请求后端接口：MCP Server 解析RPC请求参数，构造并发起 HTTP 请求调用高德API 
6. 结果反馈：MCP 返回的 POI 列表返回给 Agent，供其进一步处理
