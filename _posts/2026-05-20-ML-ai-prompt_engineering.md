提示词工程（Prompt Engineering）是告诉大模型你的意图的方法体系。

# Prompt

一个Prompt本质上是**任务描述+行为规约+输出约束**的组合。

## 提示词工作原理

1. **Token化和编码：**将用户输入的Prompt转换为 Token 序列，作为模型输入；
2. **上下文建模：**模型根据已有知识理解用户意图，建立语境；
3. **概率预测：**逐 Token 预测最有可能的输出，生成响应的内容；
4. **策略约束：**通过 Temperature、Top-p等采样策略控制生成过程；
5. **Answer Engineering：**结构化、解析、验证输出结果。

## 提示词核心组成

1. 角色 Role：设定模型的专业角色；
2. 指令明确 Directive：告诉模型意图；
3. Additional Info：背景知识、限制条件；
4. Exemplars：示例；
5. Format：输出格式；
6. Style：语气，风格（正式、简洁）。



核心结构：

| 模块                 | 内容说明                           | 示例                                     |
| -------------------- | ---------------------------------- | ---------------------------------------- |
| 上下文 Context       | 提供场景、角色、目标受众、数据来源 |                                          |
| 任务 Task            | 说明任务与交付形式                 | 实现一个支持登录的前端页面，输出完整代码 |
| 指导原则 Guidelines  | 说明风格、框架或约定               | 请保持响应式布局，不使用外部依赖         |
| 约束条件 Constraints | 硬性规则与限制                     | 输出仅单个文件                           |



## Prompt库

| 技术类型 | 可插拔 Prompt 示例 | 适用 |
|------|------|------|
| System Prompt | 严格遵循专业身份，输出结构化格式。隐藏推理，仅输出最终答案。 |  |
| Role Playing | 请以资深 AI 架构师的角度分析。你是 PM，请从用户视角评估。 |  |
| Context Prompt | 以下是背景，请结合上下文回答。 |  |
| CoT | 请逐步推理并输出思维链。 | 复杂逻辑、数学、多步骤任务、分析性问题 |
| Self-Consistency | 给出 3 个推理路径并选择最佳答案。 |  |
| ToT | 请探索至少 3 种方案并最终决策。 | 策略选择、权衡类任务、架构决策 |
| ReAct | 按 Thought → Action → Observation 结构回答。 |  |
| Code | 请生成具备注释、边界处理、错误处理的代码。 |  |
| APE | 请生成提示词的多个版本并进行自我优化。 |  |

## 输出控制

### 外约束层 - 长度控制

- 定义 Token 限制

- 停止条件：指定特定token或字符串，当前生产到该内容时立刻停止。

### 采样策略层 

Temperature: 概率分布，值越大随机性越高。

Top-K: 候选空间硬截断，值越大随机性越高。

Top-P: 概率累计分布截断，比Top-K更柔和，值越大随机性越高。

### 惩罚策略层

重复惩罚（Repetition Penalty）：降低模型重复出现的词元概率。值越大，越随机。

频率惩罚（Frequency Penalty）：用于惩罚高频词，使输出语义分布更均衡。值越大，越随机。





# Prompt Engineering

在提示词工程阶段，提示词是具备可维护、可测试的系统组件。

## Jinja2 提示词模版

Jinja2解决的核心矛盾是：提示词需要同时具备可阅读性、可复用性、动态渲染能力,而传统字符串拼接
方式在变量增多、逻辑分支复杂时完全无法维护。



## 常见问题与应对策略

| 问题       | 表现                 | 解决方案                     |
| ---------- | -------------------- | ---------------------------- |
| 幻觉       | 生成虚假不实信息     | 加强上下文约束，要求引用来源 |
| 输出不一致 | 想通输入多次结果不同 | 固定随机种子、使用更具体模版 |
|            |                      |                              |
